## Source, attribution, and sharing

The source is [CyberAgent's Crello dataset on Hugging Face](https://huggingface.co/datasets/cyberagent/crello), dataset revision `5.1.0` as pinned in `scripts/convert_crello_dataset.py`. Credit CyberAgent and the dataset authors when describing the source. The dataset card specifies CDLA-Permissive-2.0 and asks users to agree to VistaCreate's licensing terms. The card also explains that CyberAgent does not own the original templates and does not redistribute the original template files. The [CDLA terms](https://cdla.dev/permissive-2-0/) cover the dataset as a data collection; they do not grant rights to third-party design content that may appear inside it. VistaCreate's [licensing terms](https://support.create.vista.com/hc/en-us/articles/360002744694-What-are-the-licensing-terms-for-designs-made-in-VistaCreate) should be reviewed before sharing derived designs, images, or model weights.

For this project, downloaded rows, converted design JSON, extracted assets, fonts, previews, and pair manifests stay local and are ignored by Git using specific paths in `.gitignore`. Do not publish a converted copy or upload extracted design assets to a team Hugging Face repo without resolving the applicable rights. Share the scripts and instructions; have teammates download the source independently under the dataset's terms. A trained adapter can still memorize source designs, so review and get appropriate permission before publishing weights.

## What conversion keeps

`scripts/convert_crello_dataset.py` exports each source row into a renderer-oriented JSON, extracted local assets, a manifest, and the dataset's `preview` image. The preview is the image supplied by the dataset; it is not generated by our local renderer. `scripts/compare_crello_renders.py` is a separate QA utility that renders converted JSON locally and compares that result with the supplied preview. The text-model training data should use structured design/layout fields, not the preview image bytes. If a vision-model experiment uses previews, keep that pipeline and its licensing/evaluation separate.

The local conversion currently contains 19,479 train, 1,852 validation, and 1,971 test designs (23,302 total). The `crello_sample` folder is a small inspection subset, not an additional split. These are local export counts, not a claim about every record on the upstream dataset page.

## Pair scan and categories

Run `scripts/mine_verified_crello_pairs.py` over the converted split folders to make `data/crello_verified_pairs.json`. The scan groups possible counterparts using normalized titles and/or non-empty normalized text sets, then cheaply filters candidates by canvas dimensions/aspect ratio, element-count difference, and text overlap. Candidate pairs are then checked more closely:

- **Exact:** every element in both designs has a one-to-one match; text is matched using normalized text and font family while preserving authored line breaks; visual elements use downsampled 16×16 RGBA similarity (cosine threshold `0.95`); and relative stacking order is checked for elements whose bounds overlap in either design. The current code creates correspondence IDs for the pair; these are inferred matches, not upstream shared element IDs. The local manifest was additionally revalidated against converted text content, demoting pairs where text changed.
- **Core:** every text element and primary visual is matched, at least 80% of elements match, at most two small decorative elements remain unmatched, and the applicable overlap ordering check passes.
- **Rejected:** a candidate did not satisfy the exact or core criteria. Rejected means “not accepted by these rules”; it does not prove the designs are unrelated.

The scan initially found 6,348 exact, 1,851 core, and 33,827 rejected candidates. Revalidating matched text against the converted designs demoted 2,883 exact and 796 core pairs whose text content or line breaks changed. The current local manifest contains 3,465 exact, 1,055 core, and 37,506 rejected pairs (42,026 total). These remain heuristic outcomes, not human-verified ground truth. A 16×16 similarity representation can miss visual differences, and title/text grouping can produce unrelated candidates. Inspect the supplied previews and match report before treating pairs as trusted labels.

Pair locations by split are important for avoiding leakage:

| Pair scope | Exact | Core | Rejected |
| --- | ---: | ---: | ---: |
| train ↔ train | 2,352 | 735 | 26,454 |
| validation ↔ validation | 25 | 6 | 246 |
| test ↔ test | 28 | 7 | 245 |
| cross-split, combined | 1,060 | 307 | 10,561 |

For Qwen, `scripts/prepare_qwen_training.py` builds connected components over exact and core matches before assigning whole families to a stable 80/10/10 model split. That means upstream cross-split exact pairs can be used without leaking a family across train/validation/test. The exporter also skips changed text content and non-background `contain` images whose aspect ratios differ by more than 5%, projects boxes on canvas, and preserves the reference font size. Its defaults cap each source template at 2 outgoing directions within its assigned split; connected components still define split isolation. Use `--train-source-cap 0 --eval-source-cap 0` to retain every eligible direction. Core pairs remain review-only; rejected pairs are not used.

## Backplate scan

`scripts/inspect_crello_backplates.py` inspects the 100-design `crello_sample` subset. It considers an image layer only when it is behind text by z-order and contains at least 85% of the text's visible bounding box. It measures color variation, edge density, alpha fill, symmetry, and canvas area share, then classifies likely full-bleed layers, small backplates, panel candidates, or other images. “Flat/low-variance” is a candidate signal, not proof that an image is a reusable backing panel. No diagnostic result file is currently recorded, so there are no verified counts to report. Do not enable a general backplate rule based on this scan without reviewing its examples and the effect on the starter renderer.

## Model considerations

The local Qwen3-0.6B weights are an **opt-in** proposal candidate (`MAGICANVAS_QWEN_ENABLED=1`). Docker downloads the base weights during image build; Qwen remains off unless enabled. The first local v1 adapter improved JSON and coordinate metrics but produced weak rendered layouts. A new v2 training export uses normalized 0..1000 canvas coordinates, short element aliases, and explicit source overlap/alignment relations. It also expands training from 1,202 to 4,242 eligible directions without mixing connected design families across splits. A v2 adapter is now installed. The engine preserves a decoder-checked candidate and compares source-relationship, measured-font, bounded local, and contrast-repair alternatives. An optional v3 format uses geometric-mean font normalization and requires a separate newly trained adapter; it is not used with the installed v2 weights. See [QWEN_LORA_COLAB.md](QWEN_LORA_COLAB.md) for the updated training workflow.

The historical Qwen v2 export contains 4,242 train, 228 validation, and 90 test directions, plus 1,055 core review records. It skips 1,366 directions with invalid non-background image aspect changes and 204 with changed background roles. Text-changed pairs have already been demoted by the pair manifest. Exact and core matches both connect families for split assignment, while only exact pairs become supervised examples. The family-capped experiment contains 767/70/42 directions; the new source-capped v2 export contains 2,013/309/89 directions across 295/35/21 isolated families. Raw model validity is measured before runtime omission recovery, and family macro metrics supplement per-direction averages. These are projected geometry targets, not byte-for-byte copies of Crello target coordinates. Inspect held-out rendered proposals for hierarchy, spacing, containment, image proportions, and text readability before relying on a LoRA.

Treat text-layout prediction and image-quality judging as separate tasks. `scripts/index_siglip_previews.py` indexes original `preview` files by their existing split for inspection without copying or re-encoding them. The previews are positive candidates, not proof that every design is an ideal resize or universally high quality. They are used as fidelity evidence, not paired directly against local engine renders for preference training; that would let the model detect renderer differences. Previews alone also cannot teach a good-versus-bad boundary.

For resize-quality preference learning, `scripts/prepare_siglip_pairs.py` compares a converted target JSON render with its original dataset preview as a fidelity gate. It now records local grid and text-region SSIM alongside global SSIM, and rejects targets below the global 0.90 or text-region thresholds or with renderer warnings. The diagnostic renderer uses the dataset font bundle for this experiment; the production starter renderer remains unchanged. Original preview images are evidence only. The direct positive and negative training views are both local renders resized to the same pixel dimensions, so SigLIP cannot win by detecting which renderer produced the image. Keep preview images local.

The SigLIP preparation script labels an engine adaptation only when it finds a
concrete defect: text overflow, severe font shrink, contrast loss measured on a
text-free render, lost source-backed text containment, or a new unlayered
overlap. Element displacement is recorded for analysis but is not a defect by
itself. `scripts/train_siglip_ranker.py` freezes the SigLIP2 image encoder and
fits a small Bradley–Terry linear ranking head from accepted pairs; it splits
connected design families before training. A pair must pass scripted defect
checks or a human-reviewed alternative is explicitly accepted, and appears in
`data/siglip_pairs/approvals.jsonl` as
`{"pair_id":"...","decision":"accept"}` after human review. It refuses to
run until at least 20 reviewed same-domain pairs exist. Training was not started because the current
existing `data/siglip_pairs/` manifest is from the earlier preview-versus-engine
experiment and is not eligible for training. Regenerate pairs with the current
script and manually review engine candidates first. No SigLIP training has
started. The review page is for human inspection; rerendering does not relabel
a pair.

Before publishing any adapter, confirm the event rules for model and data use, the model base license, and whether training weights derived from this corpus may be redistributed. Avoid including raw previews or assets in the model repository. Keep a record of the exact source revision, pair-manifest version, filters, and train/validation/test IDs for reproducibility.
